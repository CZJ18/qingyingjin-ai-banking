# 本人账单导入与只读分析

当前独立入口为 http://127.0.0.1:30410/billing?import=1 。原 30408 版本保留。两者使用同一个明确隔离的测试数据库，本轮没有迁移或清理数据。这是本机测试应用，资金执行仍为模拟；银行直连、真实转账、理财和商户取消尚未接入。

1. 登录后，在安全中心创建一个专用的零余额模拟账户作为分析账本。不要把本人账单与演示流水混在同一个账本。这个余额不代表银行余额。
2. 在账单页明确选择该账本，上传自己有权使用的 UTF-8 CSV。可映射中文列名；必须提供交易编号、时间、金额、收支方向、币种和入账状态。银行/平台导出格式不满足这些要求时，需要先在本机整理，系统不会猜测缺失字段。

   不能读取的编码会被明确拒绝，请先在本机另存为 UTF-8；系统不会静默转换乱码。记录格式错误会指出记录序号和字段，修正后重新预览。序号以表头为第 1 条记录，带换行的引号字段可能占多个物理行。错误提示不回显交易编号、金额或商户原值。

   原始行（包括没有映射的列）会保存在本机数据库用于来源追溯。上传前请在本机移除不需要分析的敏感列；不要包含银行登录密码、支付密码、验证码或密钥。上传内容摘要及原始行摘要用于内部核对，不是银行真实性证明。
3. 核对预览后逐笔授权补录。上传、预览及 record_only 补录不会改变资金余额；来源文件和行摘要只证明上传记录的内部完整性，不证明银行真实性。
4. 当前账户已入库且内容一致的编号会在预览中跳过。同编号的金额、方向、日期或其他业务字段不一致时拒绝整次预览，不覆盖历史记录。预览与执行之间的并发仍由执行网关和数据库唯一约束保护。
5. 补录成功后，点击“查看YYYY-MM月账单”查看对应上海时区月份；按钮会恢复整月日期并清除旧分类和商户筛选，不切换账户或再次补录。在 AI 助手的“下个月想少花多少钱”输入目标并选择自愿调整的类别。当前可使用 Go 确定性规则和7天试行，不消耗模型额度。账期结束不代表数据已收全，系统尚无银行覆盖核验能力，不会据此确认可省金额。

支持的明确值：

| 字段 | 格式 |
| --- | --- |
| 金额 | 正数十进制元，例如 `15.00`；不接受货币符号、千分位或负数 |
| 方向 | `income` / `expense` 或 `收入` / `支出` |
| 币种 | `CNY` 或 `人民币` |
| 状态 | `posted` / `pending` / `reversed` / `failed` 或 `已入账` / `待入账` / `已冲正` / `失败` |
| 时间 | 带时区 RFC3339 或 `YYYY-MM-DD HH:mm:ss`；无时区时按上海时区 |

只补录已入账的人民币外部记录。请核对并排除本人账户间划转等内部流水；没有交易类型列时，系统不能替你识别这些记录。`成功`不等于银行已入账，`退款`不自动推断为收入，冲正不自动反写旧记录。最多1000行、256KiB。

上传本身不调用模型。需要真实模型解读时，仍须新的费用审批、精确数据/任务范围、执行计划独立确认及明确调用授权。账单解释工具仅发送受约束的汇总；汇总仍可能属于个人财务信息，不等于匿名数据。不要将密钥、完整环境文件或银行登录凭据写进CSV或对话。

本轮浏览器验收使用的都是明确标记的合成样本，不能称为本人真实账单验收或供应商正式消费对账。
