# Coze 调用配额与部署

生产入口由 `cmd/server` 使用 `coze.NewBudgeted`，不接受客户端指定配额 owner。所有 Coze 调用入口（编排解释、Supervisor、目标/账单/健康目标解析）在发起 HTTP 前绑定服务端用户及调用键。

先备份目标数据库，以迁移身份执行 schema 018，再启动新版本。示例：`migrate --env-file <private-env> --expected-database <exact-database>`。独立测试库另加 `--test-only`。历史 001–017 迁移未重写。018 新增两张计量表及存储冻结触发器；离线迁移表清单含这两张表。PostgreSQL 运行身份需要新表 SELECT/INSERT/UPDATE 权限，不应拥有修改 storage control 或迁移账本的权限。用迁移身份执行 DDL，不用运行身份执行。

| 配置 | 默认值 | 有效范围 |
|---|---:|---|
| BANKING_MODEL_DAILY_CALLS | 20 | 1–1000 |
| BANKING_MODEL_DAILY_TOKENS | 327680 | 1–1000000000000，且不小于单次预占 |
| BANKING_MODEL_RESERVATION_TOKENS | 16384 | 1–1000000000 |

窗口按用户和 UTC 日期划分。多进程通过数据库用户行锁串行预占；SQL 不可用、owner 不活跃或配额不足时关闭调用。幂等键绑定用户、工作流及请求摘要，同键不同参数拒绝。完成的同键请求复用经过校验的缓存；reserved/unknown 请求不再次发起。一个任务可以包含多个实际模型调用，每次分别计量；异步任务创建可能先返回 201，后续任务状态显示 MODEL_QUOTA_EXCEEDED。

成功响应的合法 token 字段结算实际用量。超时、结果丢失和无法记账保留预占；缺少 token 的成功响应也保留 token 预占，不自动退款。进程重启不会清空持久记录。unknown 不应由 Scheduler 自动重放；运营人员必须核对供应商 execute_id/账单和审计后处理，不要直接删除配额表。日志只记录 owner/reservation ID，原始响应缓存是受用户绑定的敏感数据库数据，应限制访问并制定备份及保留策略。

这是严格的每日调用次数上限及基于预占的 token 预算，不是供应商货币账单硬上限。预占值应覆盖已发布工作流的模型步数和单步 token 上界。上游实际用量超过预占时如实记入债务并限制后续调用，无法追回已发生的超额。`cost` 只保存上游字符串，不代表真实发票金额。直接供应商调用及其他系统不受此组件控制。

隔离实例通过回归不代表旧运行镜像已更新。发布时检查镜像 Go 版本、schema 18、新表权限、所有工作进程配置一致，然后复核身份失效、正常只读调用、累计拒绝和未知结果恢复。共享任务库的工作进程可以互相领取任务，因此不能把模拟 Coze 与真实 Coze 工作者放在同一任务库中同时验证供应商边界。
